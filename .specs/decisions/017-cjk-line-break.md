# ADR-017 — CJKの改行を描画時に詰める

Status: **Accepted**（2026-09-10）

Related: U-004, U-023, ADR-012, `product/principles.md` §5 / §6 / §10,
`product/requirements.md` §3.3 / §5（Non-goals）

## Context

Markdownでは、段落内の改行（soft break）は空白1つとして描画される。
英文では語の区切りとして正しいが、日本語では語の間に不要な空きが入る。

このため日本語で書くとき、次のどちらかを選ばされていた。

- 「1文1行」で書く（推敲もdiffも見やすい）→ 表示に余計な空白が入る
- 1段落を1行の長文で書く → 表示は正しいが、折り返し頼みの編集になる

つまり表示の不具合ではなく、**書き方の選択肢を1つ潰していた**。
日本語で書くコストとして無視できない。

実測（本リポジトリの remark-parse 11 / remark-gfm 4）:

```text
行1
行2
```

→ `<p>行1(改行)行2</p>` となり、ブラウザは改行を半角空白1つとして描画する。

## Decision

**CJK同士に挟まれたsoft breakだけを、空白を残さずに詰める。**

判定と実装は `domain/document/markdown.ts` の `compactCjkLineBreaks`。
mdastの段階で、`text` 節点の `\n` の前後1文字を見る。

### 1. 詰めるのは両側がCJKのときだけ

英文の語間の空白はそのまま残す。`日本語\nEnglish` のように片側がCJKでない並びも残す。
ここで詰めると単語がくっつくため。

CJKと見なす範囲は U+2E80–303F / U+3040–30FF / U+3400–4DBF / U+4E00–9FFF /
U+F900–FAFF / U+FF00–FFEF。句読点・鍵括弧・全角形を含む。

### 2. inline要素をまたぐ改行も同じ扱いにする

`日本語の文で\n**強調**が続く` のように行末がinline要素で切れていても、
書き手から見た改行の意味は変わらない。節点をまたいで前後の1文字を見る。

### 3. hard breakには触らない

行末2スペース（`break` 節点）は改行のまま残す。明示的に改行を書いた意図を消さない。

### 4. ファイルには一切触らない

**これはMarkdown方言の追加ではなく、描画時のCJK組版**として入れている。
ファイルの中身はCommonMarkのまま変えない（principles.md §5「No surprising file mutations」）。
`requirements.md` §5 の Non-goals「独自Markdown方言の大量追加」には当たらない。

## Consequences

- 日本語を「1文1行」で書けるようになった。書き方の選択肢が戻った
- **他のツール（GitHub等）で開くと、これまで通り空白が入る。** 表示がQuietだけ違う
- `renderMarkdown` を通る経路すべてに効く。現在はPreviewのみ
- コードブロック（`code` / `inlineCode`）は `text` 節点ではないので影響を受けない

### 未決（要判断）

**Settingsにoffを持つかどうかは決めていない。**
「他ツールと同じ見え方に揃えたい」需要があるなら設定が要るが、
設定項目を安易に増やさない方針（AGENTS.md §4）とぶつかる。
実際に他ツールへ貼る場面が出てから判断したい。

## Alternatives

### `remark-breaks` を入れて、すべての改行を `<br>` にする

1行で済むが、CommonMarkから外れる。英文でも意図しない改行が入り、
GitHub等での見え方との食い違いが日本語以外にも広がる。
この1点のために払う代償として大きい。

### CSSで処理する

**原理的にできない。** 改行由来の空白と、書き手が打った半角スペースは、
HTMLになった時点で同じ1文字であり、`white-space` では区別できない。

### 何もせず「段落は1行で書く」を運用で守る

費用ゼロだが、課題そのものが残る。Contextに書いた選択の強制がそのまま続く。
