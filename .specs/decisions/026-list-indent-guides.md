# ADR-026 — 箇条書きの字下げの視認性向上

Status: **Accepted**（2026-09-23）

Related: ADR-006, `ui/ui-spec.md` §7, `quality/acceptance-criteria.md` §C

## Context

エディタで箇条書きや番号付きリストを入れ子にした際、各項目の深さを目視で把握しにくい。原因は次の2点である。

- 深さを示す手がかりが行頭の空白幅しかなく、階層が深くなると同一階層の項目を縦方向に追跡しにくい。
- 折り返し有効時、長い項目の2行目以降が行頭に戻るため、次項目や親項目と識別しにくい。

## Decision

### 1. 折り返し行を本文の開始位置にそろえる

リスト項目が折り返された際、2行目以降は marker の後ろの本文開始位置にそろえる。task list では `[ ] ` の後ろにそろえる。marker を持たない継続行は、その行自身の字下げ位置にそろえる。

この規則はすべてのリストに適用する。折り返しを無効にしている場合は表示に変化はない。

### 2. カーソルがある箇条書き内に限定して縦線を表示する

子リストを持つ項目では、子リストの範囲の左側かつ親 marker の直下に細い縦線を表示する。線の色には境界線と同じ `--border` を使用する。

縦線は、カーソルを含む最も外側のリスト内でのみ表示する。カーソルがリスト外にある場合や、別のリストにある場合は表示しない。

### 3. 行の構造を構文木から取得する

各行の深さと本文の位置は、エディタの Markdown 構文木から取得する。行頭の空白を正規表現でカウントする手法は、リスト内のコードブロックや字下げのない継続行を誤判定するため採用しない。

## 採用しなかった案

- **すべてのリストに常に縦線を引く**: 階層は把握しやすくなるが、長い文書では線が増えて視覚的ノイズになるため不採用とした。
- **深さごとに marker の記号を変える（`•` `◦` `▪` など）**: 入力文字と異なる記号が表示され、Markdown をそのまま表示する方針に合わないため不採用とした。
- **深さごとに色を変える**: 階層が深くなるほど画面表示が煩雑になり、本文を多色にしない方針（`ui/ui-spec.md` §8）に反するため不採用とした。

## Consequences

- 設定項目は追加しない。
- 縦線はカーソルの移動に連動して表示・非表示が切り替わる（文字位置は変動しない）。
- Preview の表示は変わらない。
