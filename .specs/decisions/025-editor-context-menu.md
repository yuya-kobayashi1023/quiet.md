# ADR-025 — エディタ本文の右クリックメニュー

Status: **Accepted**（2026-09-23）

Related: U-003, U-025, ADR-007, ADR-010, `ui/ui-spec.md` §7, `ui/interactions.md` §13, `quality/acceptance-criteria.md` §C

## Context

エディタ本文領域の右クリックメニューには、現在 WebView2 の既定メニューが表示されており、以下の課題がある。

- Quiet の Design system と整合せず、OS の言語設定による日本語と英語の混在や、「名前を付けてページを保存」など本アプリで不要な項目の表示が発生している。Custom title bar（ADR-010）を採用した UI 全体とも調和していない。
- Markdown 書式適用の導線がなく、太字などの操作も記号の手入力に限られ、ショートカットも割り当てられていない。

なお、Sidebar には既に Quiet 独自の Context menu（`ui/interactions.md` §13）が実装されており、位置合わせおよび閉じる処理の仕組みが存在する。

## Decision

### 1. 本文領域の右クリックを Quiet のメニューに置き換える

ブラウザの `contextmenu` イベントを抑止し、Sidebar と同様に `.context-menu` スタイルを適用したメニューを表示する。位置合わせおよび閉じる処理（Escape キー、外側クリック、画面端での内側への補正）は Sidebar の仕組みを共有する。

対象は Write および Split の編集面のみとし、Preview、Metadata、Status bar、Find bar の右クリックメニューは変更しない。

### 2. 項目

```text
元に戻す              Ctrl+Z
やり直す              Ctrl+Y
──────────
切り取り              Ctrl+X
コピー                Ctrl+C
貼り付け              Ctrl+V
──────────
太字
斜体
インラインコード
リンク
──────────
引用
箇条書き
チェックリスト
──────────
"◯◯" を検索
```

各項目の挙動および制御は以下のとおりとする。

- **"◯◯" を検索**: テキスト選択時のみ表示する。選択文字列を Find bar（U-025）へ渡して開き、選択文字列が長い場合は表示を省略する。
- **有効・無効の制御**:
  - 切り取り、コピーは、非選択時には無効（押せない状態）とする。
  - 太字、斜体、インラインコードは非選択時も押下できる。§4 のとおり記号のみを挿入し、カーソルを記号の内側に配置する。
  - 元に戻す、やり直すは、履歴が存在しないときに無効とする。
- **目次**: 項目に含めない。Top bar から開く導線が既に存在するため、二重配置を避ける（`AGENTS.md` §4）。

### 3. 右クリックした位置へカーソルを移動する

メニュー項目の対象を開く前の表示状態と一致させるため、右クリック時のカーソル位置を以下のように制御する。

- 選択範囲外を右クリックした場合: クリック位置へカーソルを移動してからメニューを表示する。
- 選択範囲内を右クリックした場合: 選択状態を保持したままメニューを表示する。

### 4. 書式項目をトグル動作にする

書式項目はトグル（付与／解除）として動作させる。

- **インライン書式**: 選択範囲を `**` などの記号で囲み、既に同一記号で囲まれている場合は解除する。非選択時は記号のみを挿入し、カーソルを記号の内側に配置する。
- **リンク**: `[選択した文字](url)` を挿入し、`url` 部分を選択状態にする。非選択時は `[](url)` を挿入し、同様に `url` を選択状態にする。
- **ブロック書式（引用、箇条書き、チェックリスト）**: 選択範囲に含まれるすべての行（非選択時は現在行）の行頭に対して `> `、`- `、`- [ ] ` を付与または削除する。対象行のすべてが既に同一の接頭辞を持つ場合のみ解除する。

### 5. ショートカットは追加しない

メニュー内に表示するショートカットは既存のものに限定し、書式項目には割り当てない。

`Ctrl+B` は既に Sidebar の開閉に割り当てられており（`ui/desktop-ux.md`）、一般的な太字操作に利用できない。空きキーを用いて独自の体系を設けると、`Ctrl+B` を太字と想定して押下したユーザーが誤ってサイドバーを閉じる混乱を招くため、書式ショートカットの導入は本 ADR の対象外とする。

### 6. クリップボードから再取得して貼り付ける

WebView 環境では `document.execCommand("paste")` が機能しないため、`navigator.clipboard.readText()` で読み取った文字列を CodeMirror の transaction として挿入する。

画像の貼り付け（AUTO-050）やリンクの貼り付け（`link-paste`）は `paste` イベントに依存しているため、右クリックメニューからの貼り付けは文字列のみを対象とする。クリップボードの読み取りに失敗した場合は Toast で通知する。

### 7. スペルチェックの修正候補は非表示となる

独自メニューへの移行に伴い、WebView2 の既定メニューが提供していたスペルチェックの修正候補は表示されなくなる。

`spellCheck` 設定による赤波線表示は継続するが、修正候補を JavaScript から取得する API が存在しないため独自メニューとは両立できない。設定が on の場合でも誤りの検知にとどまり、修正は手動入力で行う必要がある。

### 8. 純粋ロジックを domain 層に配置する

書式適用の純粋ロジックを `src/domain/document/inline-format.ts`（囲み記号の付け外し）および `src/domain/document/line-prefix.ts`（行頭接頭辞の付け外し）に配置し、CodeMirror との接続処理から分離して単体テストを可能にする（`AGENTS.md` §7、`list-editing` と `list-keymap` の責務分離に準拠）。

## Consequences

- 右クリックメニューからの開発者ツール呼び出しは利用できなくなる（Tauri の dev build では `F12` などの既存経路が引き続き利用可能）。
- 項目数の増加に伴い、本文のメニューは Sidebar よりも縦長となる。画面下端付近で開く場合は上方向へ位置を補正する。
- 書式の付け外しは文字列操作として処理し、Markdown の構文木（AST）は参照しない。そのため、コードブロック内で太字を適用した場合は記号がそのまま挿入される。

## Alternatives

### 既定のメニューを維持する

不採用。スペルチェックの修正候補は保持できるが、Design system と整合しない外観や、無意味な項目が表示される状態が解消されない。

### Tauri のネイティブメニューを使用する

不採用。Tauri 2 の `Menu` は OS のネイティブメニューであり、Quiet のテーマ、角丸、影と統一できない。Custom title bar を自前で描画している方針（ADR-010）とも乖離する。

### 編集操作のみとし、書式項目を含めない

不採用。切り取り、コピー、貼り付けのみの提供では、既定メニューの置き換えによって失われる利点（スペルチェック候補）に見合わない。

### 書式のショートカットも同時に追加する

不採用。`Ctrl+B` が既に割り当て済みであり、書式ショートカット全体の体系設計が別途必要となる。まずはメニューからの導線を先行して提供し、利用状況を踏まえてから判断する。
