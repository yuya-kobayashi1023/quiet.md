# ADR-024 — Sidebar のファイル行をまとめて選択する

Status: **Accepted**（2026-09-23）

Related: U-005, U-024, ADR-013, ADR-019, ADR-020, ADR-023, `ui/ui-spec.md` §2, `ui/interactions.md` §12 / §13, `architecture/interfaces.md` §5

## Context

複数のノートをまとめて Archive へ入れる手段も、戻す手段もない。1 件ずつ右クリックしてアーカイブを選択する操作を繰り返す必要があり、整理コストが件数に比例して増加している。

Archive は実体の移動を伴わない論理 flag であり（U-005）、ピン止めも同様の flag である（ADR-020）。これらはいずれも対象を複数に広げても操作の意味が変わらないため、一括で処理できる。

一方、1 件にのみ意味を持つ操作（開く・名前を変更）や、実行回数に応じて副作用が増加する操作（新しいウィンドウで開く・複製）は、一括処理すると結果が予測しにくい。

## Decision

### 1. 選択対象は Notes と Archive のファイル行のみ

フォルダ行、Recent 行、Workspace 行は選択対象としない。

一括操作の対象は Workspace metadata が保持する相対パスの flag（`archived` / `pinned`）であり、フォルダや Recent には適用できない（ADR-013 §Archive、ADR-020 §5 と同様の理由）。フォルダ行を選択可能にした場合、折りたたまれたフォルダ内のファイルまで巻き込まれ、影響件数を把握できないまま操作することになる。

Notes と Archive をまたいだ選択を可能とし、アーカイブ済みと未アーカイブが混在した選択も許容する。

### 2. Ctrl+クリックで増減、Shift+クリックで範囲選択

| 操作 | 結果 |
|---|---|
| クリック | 従来どおりそのノートを開く。選択は解除する |
| Ctrl+クリック | その行を選択に追加する（選択済みの場合は解除）。起点をその行に設定する |
| Shift+クリック | 起点からその行までを選択範囲とする。起点は変更しない |

Ctrl+クリックおよび Shift+クリックではノートを開かない。開く操作は修飾キーなしのクリックのみが担う。

macOS では Meta（Command）キーを Ctrl と同様に扱う。

### 3. 範囲選択の基準は「現在表示されている行の並び」

Shift+クリックの選択範囲は、操作時点で Sidebar に表示されているファイル行の並び順で決定する。Notes と Archive は連続した 1 つの並びとして扱う。折りたたまれたフォルダ内のファイルは並び順に含まれず、選択範囲にも入らない。

表示されている行のみを対象とする一貫性を優先する。選択中のファイルがフォルダの折りたたみによって非表示になった場合も、表示されている行のみを有効な選択として扱い、非表示になった行には操作を適用しない。

### 4. 選択の解除条件

選択は以下のいずれかで解除する。

- Escape
- 修飾キーなしのクリック
- 一括操作の完了
- Workspace の切り替え

### 5. 選択中の行は Active 行と異なるスタイルで表示する

選択中の行は、左端の accent 罫線と淡い背景で表示し、Active 行（`--selected` の背景）と明確に区別できるようにする。accent は罫線の幅にとどめ、表示面積を広げない（`AGENTS.md` §8）。

Active かつ選択中の行には、両方の表示スタイルを重複して適用する。

### 6. 右クリックの挙動を選択の内外で分岐する

右クリック操作の対象は、クリック位置が選択の内か外かに応じて決定する。

- 選択内の行を右クリック: 選択全体に対するメニューを表示する
- 選択外の行を右クリック: 選択を解除し、その 1 件に対する従来のメニューを表示する（`ui/interactions.md` §13）
- 選択が 1 件以下の場合: 従来のメニューを表示する

### 7. 一括操作メニュー

```text
3 件を選択中
──────────
アーカイブ
アーカイブから戻す
──────────
ピン止め
ピン止めを外す
──────────
パスをコピー
──────────
選択を解除
```

先頭の件数は見出しであり、クリックできない。

「アーカイブ」は、選択内に未アーカイブのファイルが 1 件以上ある場合のみ表示する。「アーカイブから戻す」は、アーカイブ済みのファイルが 1 件以上ある場合のみ表示する。ピン止めおよびその解除も同様の規則で出し分ける。双方が混在する選択では両方の項目を表示する。

「パスをコピー」は、選択したファイルのフルパスを改行区切りで 1 回の書き込みにまとめる。並び順は Sidebar の表示順とする。

「開く」「新しいウィンドウで開く」「名前を変更」「複製」「エクスプローラーで表示」は表示しない。1 件にしか意味を持たないか、実行回数に応じてウィンドウやファイルが増加するためである。破壊的な Delete も引き続き表示しない（`ui/interactions.md` §13）。

### 8. 一括アーカイブの Toast に Undo を提供する

一括アーカイブの実行時には `N 件をアーカイブしました  元に戻す` を表示する。Undo はその時点で対象とした相対パスのみを元に戻すため、操作中に選択状態が変化していても影響を受けない。

アーカイブから戻す操作の Toast には Undo を配置しない。ピン止めおよびその解除にも配置しない（右クリックから同じ操作で元に戻せるため。ADR-020 §3 と同様の理由）。

### 9. 選択の計算を純粋関数に分離する

選択状態の計算は `src/domain/document/selection.ts` に配置し、React や CodeMirror から分離してテスト可能にする（`AGENTS.md` §7）。

```ts
export interface SidebarSelection {
  /** 選択中の相対パス。いま見えている行の並び順に保つ。 */
  readonly paths: readonly string[];
  /** Shift 範囲の起点。 */
  readonly anchor: string | null;
}

export type SelectionClick = "plain" | "toggle" | "range";

export function nextSelection(
  current: SidebarSelection,
  /** いま見えているファイル行の相対パス。Notes → Archive の順。 */
  order: readonly string[],
  clicked: string,
  click: SelectionClick,
): SidebarSelection;
```

選択状態そのものは Workspace metadata に保存せず、セッション内の UI 状態として扱う。

### 10. Native の flag 更新を一覧で受け取る形式に変更する

`setArchived` および `setPinned` の引数を、相対パス 1 件から相対パスの一覧（配列）へと変更する。

```text
setArchived(relativePaths: string[], archived: boolean) -> WorkspaceMetadata
setPinned(relativePaths: string[], pinned: boolean) -> WorkspaceMetadata
```

1 件ずつ呼び出すと件数分の `workspace.json` の読み書きが発生し、途中で失敗した際に一部のみ反映された状態が残る。1 回の書き込みにまとめることで、Undo 時にも対象を確実に元に戻せる。

単一パスを受け取る従来のシグネチャは残さず、既存の呼び出し側をすべて一覧渡しへ移行する。1 件は要素 1 つの一覧として表現できるため、2 つの契約を並存させる理由がない。

## Consequences

- `WorkspaceService.setArchived` および `setPinned` の signature が変更され、単体アイテムの Context menu からの呼び出しも一覧渡しとなる。
- 選択状態を相対パスで保持するため、選択中に外部でファイルが増減しても、削除されたファイルは表示行から外れ、操作対象から自動的に除外される。
- 選択状態は Sidebar 内に限定され、Search All、Command Palette、Preview には及ばない。
- Sidebar のファイル行は `<button>` のままとする。`role="listbox"` に変更すると、フォルダ行との親子関係を表現できなくなるためである。選択件数はメニュー先頭の見出しで提示する。

## Alternatives

### チェックボックスを常設する

不採用。ファイル整理は定常的な作業ではないため、その目的で全行に常設 UI を追加することは `AGENTS.md` §4 の順序に反する。

### ドラッグの矩形選択

不採用。行が 1 列に並ぶため、Shift による範囲選択で同等の操作が可能である。また、ドラッグ操作はフォルダの並べ替えと誤認されやすい。

### フォルダ行を選んで配下ごと操作する

不採用。折りたたまれたフォルダでは影響件数を把握できない。フォルダ単位でまとめたい場合は、フォルダを開いて先頭と末尾を Shift+クリックすれば十分である。

### まとめて削除を追加する

不採用。破壊的な Delete は MVP では提供しない方針を維持する（`ui/interactions.md` §13）。誤った選択に対して取り返しがつかないためである。

### 選択を Workspace metadata に保存する

不採用。選択は整理作業の間のみ意味を持つ状態であり、再起動時に復元されても誤操作の原因になるためである。
