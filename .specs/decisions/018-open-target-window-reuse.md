# ADR-018 — 外から渡された対象は既存 Window で開く

Status: **Accepted**（2026-09-15）

Amends: ADR-013 §2 / §3

Related: U-001, U-011, U-021, ADR-013, ADR-016, `ui/desktop-ux.md` §7 / §8, `ui/ui-spec.md` §2

## Context

ADR-013 §3 で定めた対象の割り当て順は以下のとおりである。

1. 同じファイルを開いている Window があれば最前面に表示する（U-021）
2. 文書を開いていない Window があれば、その Window へ渡す
3. いずれにも該当しない場合は新しい Window を作成する（U-011）

この規則には以下の課題がある。

- **不要な Window の増加**: 文書を開いた状態でエクスプローラーから2つ目の `.md` をダブルクリックすると、条件2を満たす Window が存在しないため、必ず条件3が実行されて Window が新規作成される。エクスプローラーからのダブルクリックは別ファイルを参照する操作であり、複数 Window の並列表示にはアプリ内の `Open in New Window` を用いるため、不要な Window が生成される挙動は望ましくない。
- **ファイル所属情報の無視**: 現在の Workspace 外のファイルは単体ファイルとして開き、Recent に追加される（ADR-013 §5）。そのため、過去に開いた別の Workspace 内にあるファイルであっても所属が無視されて単体ファイル扱いとなり、Sidebar に同 Workspace 内のノートが表示されず、Workspace 内検索も機能しない。
- **Native 実装の制約による上書き**: Workspace root と watcher はプロセスごとに1つしか存在しない。そのため、異なる Workspace を開いた Window が複数存在すると、後から開いた Window が先行する Window の書き込みスコープおよび監視設定を上書きする。

## Decision

### 1. 割り当て先を「最後に focus した Window」とする

対象の割り当て順を以下のように変更する。

1. 同じファイルを開いている Window があれば最前面に表示する（U-021、変更なし）
2. 最後に focus した Window へ渡す
3. Window が1つも存在しない場合のみ、新しく作成する

「文書を開いていない Window を優先する」規則は廃止する。直前に文書を閉じて一時的に空になった Window を直近まで操作していた Window より優先する妥当性はなく、判定条件を1段階減らすことで挙動を予測しやすくするためである。

最後に focus した Window を特定するため、Native 側で Window の focus 順序を保持する。破棄された Window は順序から除外する。

割り当て先は `main` に固定しない。`Open in New Window` で複数 Window を開いている利用者の `main` を奪うことを防ぎ、直近で操作していた Window に渡すことで割り当て先を予測可能にする。

### 2. ファイルが所属する Workspace への自動切り替え

開く対象のファイルが現在の Workspace 外にあり、かつ Workspace 履歴（ADR-016、App settings、10 件）のいずれかに含まれている場合は、該当する Workspace へ切り替えてから開く。

- 現在の Workspace 内にあるファイルは切り替えを行わず、現在の Workspace を最優先とする。
- 複数の履歴に含まれる場合は、最もパスが深い（root が長い）ものを選択する。これにより、入れ子構造の Workspace で外側へ切り替わるのを防ぐ。
- いずれの履歴にも属さない場合は、従来どおり単体ファイルとして開いて Recent へ追加する（ADR-013 §5）。
- 切り替え先のフォルダが存在しない場合は、履歴から除外して Toast で通知し、対象ファイルは単体ファイルとして開く（ADR-016 §8 と同一の扱い）。

判定に使用するのは App settings の Workspace 履歴のみとする。親フォルダを遡って `.quiet/workspace.json` を探索する方式は採用しない。ADR-013 で「親フォルダを暗黙に Workspace として開く」方針を却下した理由と同様に、意図しないフォルダが Workspace へ昇格するのを防ぐためである。履歴の 10 件で不足する実害が生じた時点で追加を検討する。

### 3. 起動時と実行中における処理規則の統一

外部から対象を受け取ったあとの処理規則は、起動時と実行中で統一する。ADR-013 §2 で規定した「起動時は pull、実行中は event」は通知の受け取り方式の違いにすぎないためである。本 ADR §2 で定めた Workspace 追従は、関連付け起動（未起動状態からの起動）および二重起動のいずれでも同様に機能させる。

関連付け起動における動作を、従来の「前回の Workspace を開いてから対象ファイルを開く」手順から、「ファイルが所属する Workspace が存在すればそちらを開き、存在しなければ前回の Workspace を開く」手順へ変更する。

## Consequences

- エクスプローラー上でファイルを連続ダブルクリックして複数 Window を並べる操作は行えなくなる。Windows のエクスプローラーはダブルクリック時の修飾キーをコマンドライン引数へ渡さないため、この導線を維持する手段がない。複数 Window の作成はアプリ内の `Open in New Window` および `Ctrl+Shift+N` に集約される。
- U-011 は維持される。Window あたりの同時表示文書数は 1 のままであり、Tabs は増加しない。
- U-021 は維持される。割り当て順の第1段階（同一ファイルを開いている Window の最前面化）は変更しない。
- Recent に記録されるのは「既知のいずれの Workspace にも属さないファイル」のみとなる。所属が判明しているファイルは Notes 側に表示される。
- Window の増加が抑止されるため、プロセスあたり1つしか存在しない Workspace root と watcher の競合に遭遇する機会は減少する。ただし根本的な解決ではなく、`Open in New Window` で異なる Workspace を開いた場合には同様の問題が発生するため、別途の課題として扱う。

## Alternatives

### 常に `main` window へ渡す

実装規模は最も小さいが、複数 Window を開いている利用者の `main` を奪うことになるため採用しない（Decision §1 参照）。

### 「空いている Window を優先」を残し、新規作成のみを廃止する

割り当て順の3段階を維持し、最終段階の新規作成のみを差し替える案。空いている Window を直近まで操作していた Window より優先する妥当性がなく、割り当て先が予測しづらい問題が残るため採用しない。

### ファイルの親フォルダを Workspace として開く

ADR-013 の Alternatives と同様の案。ユーザーが Workspace と認識していないフォルダに `.quiet/workspace.json` が生成されるため採用しない。

### 修飾キーにより新しい Window で開けるようにする

Windows のエクスプローラーはダブルクリック時の修飾キーをコマンドライン引数へ渡さないため、実現手段がなく採用しない。
